These are gateway-mode engine captures, not OAuth-mode CLI captures. They prove the exact headers and bodies emitted by those invocations and CPA's outbound transformation under fake serving-account OAuth credentials. They support the gateway-based read-only lane more directly than the signed-in CLI pool, but do not establish the actual lane invocation's wire shape: the lane environment currently sets a placeholder bearer and does not set the captured CLI's one-hour TTL override. The lane's read-only tools also differ.

They cannot establish what a native signed-in OAuth CLI sends directly to Anthropic, whether it already supplies OAuth/cch/request-ID fields, or whether it chooses other cache betas. They do not prove successful upstream acceptance, subscription metering, signed-in desktop UI routing, connectors, or live failover. Neither an extra gateway-to-OAuth credential field nor the generated first-party request ID alone establishes a defect in today's OAuth CLI pool.

Fixtures replace only device/session identifiers, working and memory paths, and email strings. Header/body session replacements agree. Host is represented in provenance, not copied as an ordinary header. Original source hashes identify the untouched captures. Old capture logs are retained in desktop-wire-results/superseded-capture-run/; they are obsolete evidence.

Patch comparison and recommendation

The smaller repository patch recognizes claude-desktop-3p, preserves its session and beta negotiation, and adds detector/session tests. The fuller supplied patch adds desktop sampling bypasses and transport-header preservation. Both apply cleanly to v7.3.18 and v8.0.3. Both give the same classified results on all corrected captures. There is no measured benefit here from the extra sampling/transport changes: sampling fields are absent and compression values already match.

Production gate remains unresolved. Both patches make the existing plain-desktop token-count case return HTTP 204 where the gate test requires 403. Stock passes. All three real Messages fixtures pass the gate in every build. No corrected token-count capture exists; this policy expansion remains a separate adoption blocker.

(a) Today's CLI pool: retain its current v7.3.18 build; the configured version and installed build symlink were checked read-only. This experiment finds no CLI identity/capability defect and no improvement from either desktop patch or v8.0.3 for this fixture. A direct OAuth-mode baseline is still needed for a full fidelity claim. (b) Read-only lane: retain the existing gateway-to-OAuth adaptation; these captures support account/device/OAuth/cch rebinding and identify request-ID generation as transport bookkeeping, not a desktop identity bug. Capture the exact lane invocation before claiming full equivalence, especially because its environment lacks this CLI fixture's TTL override. (c) Pooled desktop: prefer the smaller patch as the reviewed candidate: it fixes every observed identity/capability mismatch. Resolve the token-count gate policy with captured coverage, then validate the real desktop path before installation. The fuller patch and v8.0.3 add no demonstrated benefit in this matrix.
